- TypeScript/Vite production build and Rust Windows release compilation pass.

## Real local AI evaluation

An isolated actual SQLite database contains English and Arabic products, separate purchase batches and multi-line CR sales. The assistant receives fresh approved snapshots; the test asserts that chat never modifies the database. Queries cover the customer's original example, English/Arabic names and digits, product models, partial and approximate names, missing codes, ambiguity, listed selections, group followups, real FIFO value/revenue/profit/history/CR figures, monthly selection, manual application guidance, unrelated requests and SQL/instruction attacks. Killing only the owned model child verifies automatic recovery and retained context.

The final planner uses one schema-constrained conversational request, plus a semantic scope check where necessary. Facts and workflow instructions are generated by validated backend functions. Comparing the same 41 cases with this planner:

| Model | Passed | Startup | Median answer |
|---|---:|---:|---:|
| Qwen3-1.7B Q4_K_M | 33/41 | 2.09 s | 1.54 s |
| Qwen3-4B-Instruct-2507 Q4_K_M | 41/41 | 3.04 s | 2.90 s |

The earlier Qwen3-0.6B Q8_0 evaluation passed 14/41 with an earlier planner; its score is not a controlled same-prompt comparison. The 4B model is selected for Windows because the smaller evaluated models made material conversation errors. Passing this finite suite does not guarantee understanding of every possible phrase.

The final bundled-model run passes **47/47** checks, adding six phrases absent from the prompt examples: indirect delivery guidance, Arabic search guidance, a new stock-balance expression, an English-to-Arabic value followup, an external receipt expression, and an unrelated travel request. The database remains unchanged and owned-process recovery retains context.

Hardware: Windows Intel Core i9-13900HX, 32 GB RAM, CPU inference with four threads, 4096 context tokens and no GPU offload. The 4B process used approximately 4.8 GB resident memory during inference. Other development workloads affected some timings; they are not promises for an Intel i5. Models are loaded from local resources only. A 2048-token low-memory profile and platform-specific CPU runtimes are prepared.

## Native Windows and speech checks

The actual development app opens directly to Dashboard without credentials, preserves the existing business database and automatically becomes AI Ready. The active database migrated to schema v2 with zero existing business products and no authentication tables; the full pre-migration backup remains available. Stock/accounting behavior is exercised against real isolated SQLite fixtures to avoid adding fictitious customer inventory.

Native Voice Mode reaches Listening automatically after Start Conversation. End Conversation cancels active microphone capture and removes its owned worker. Closing the app removes its owned llama.cpp child while leaving the independent evaluation process running. Windows canonical resource paths were tested and simplified after local-path validation because CTranslate2 does not accept the extended Windows path prefix.

The packaged voice worker was separately tested with the actual Windows audio devices: initialization, English and Arabic PCM synthesis/playback, microphone capture returning honest no-speech on silence, and clean shutdown all succeeded. Synthetic English and Arabic utterances were synthesized by the actual bundled TTS and transcribed by the actual offline Whisper small model; Arabic contained a minor transcription spelling error. No human spoken conversation or subjective listening-quality acceptance was performed, so ChatGPT-level quality is not claimed.

PDFs were rendered with Poppler and visually inspected, including Arabic names, wrapped long descriptions, repeating table headers and a 12-page stress report. XLSX exports are genuine workbooks with selected-month data and correct totals.

## Installer and remaining acceptance

The supported Windows package is the single-file Inno Setup EXE built by scripts/build-windows.ps1. It includes the selected GGUF, CPU llama.cpp runtime, packaged speech worker/dependencies/models, licenses/corresponding source and the offline Microsoft WebView2 installer. The database is kept outside the installation directory. The installed candidate completed with exit code 0, opens at http://tauri.localhost/ without login, automatically becomes AI Ready using installed resources, saves only bundled/performance-profile settings, and replaces the previous uninstall registration with version 2.0.0. All 2,555 installed resource files matched source sizes and SHA-256 hashes. Final installer size, hash and further installed-app checks are recorded beside the delivered installer in deliverables/VALIDATION.md after packaging.

A clean Windows machine/VM installation with the network disconnected, including the case where WebView2 is initially absent, remains a deployment acceptance check. The existing Windows machine already has WebView2. The installer is unsigned. Microphone permission denial and real human repeated bilingual voice turns still need customer/hardware acceptance. No macOS build or physical Mac test has occurred; the Intel Mac build preparation is documented separately. Exact customer RAM/macOS/year must be confirmed before Mac deployment.

## Reproduce

Run `npm test`, `npm run build`, `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/desktop.ps1 test`, and the opt-in `test-ai` task. The real-model test uses bundled files and never downloads a model. See tests/ui-README.md for the browser fixture workflow; run `python -m unittest discover -s voice -p test_transcribe.py` in the reviewed developer voice environment. Build the offline installer with `npm run desktop:build`.
